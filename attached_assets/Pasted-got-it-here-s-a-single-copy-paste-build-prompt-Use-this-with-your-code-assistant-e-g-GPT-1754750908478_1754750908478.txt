# Build Prompt: Retirement Planning Web App (Phase‑1)

You are a **senior full‑stack engineer**. Generate a production‑ready **Next.js + React** app that collects client inputs and renders a simple, visual **retirement plan**. Do not skip files. Include README with setup steps.

## Objectives

* Two plan modes: **Quick Plan** and **Detailed Plan**.
* Any skipped numeric field → treat as **0**; any skipped assumption → pull from **CRM defaults API**.
* **Net Worth line chart** (stock‑like) with icons for events: mini‑retirement, child education, child marriage, retirement start.
* **Lead capture**: gate PDF export behind name, email, phone (push to CRM).
* **Login/Sign‑up**: email + password (basic).
* **Theme**: professional, light UI (light blue, light green, white).

## Tech & Libraries

* Next.js (App Router), TypeScript, TailwindCSS.
* Form: React Hook Form + Zod validation.
* Charts: lightweight (e.g., Recharts).
* Auth: next-auth (email/password Credentials provider).
* DB: Prisma + Postgres (Neon/Supabase).
* PDF: server‑side HTML → PDF (e.g., @react-pdf/renderer or Puppeteer).
* API: Next.js route handlers (/api/\*).

## Pages & Routes

* `/` – Landing with CTA “Create Quick Plan” + lead magnet explainer.
* `/signup`, `/login`, `/logout`
* `/plan/new?mode=quick|detailed`
* `/plan/[id]` – Dashboard view
* `/settings/crm` – Admin page to edit defaults (guard **admin** role)
* API:

  * `GET /api/crm/defaults` (inflation, life\_expectancy, returns, tax defaults)
  * `POST /api/lead`
  * `POST /api/plan` (create)
  * `GET /api/plan/:id` (read)
  * `PUT /api/plan/:id` (update)
  * `POST /api/calc` (return calculated timeline + markers)
  * `POST /api/export/pdf`

## Data Model (Prisma)

* User { id, name, email (unique), role: 'client'|'admin', createdAt }
* Scenario { id, userId, name, mode: 'quick'|'detailed', createdAt, updatedAt }
* Assumptions { scenarioId, inflationHeadline, inflationEdu, inflationHealth, returnPre, returnPost, lifeExpectancy, taxRegime, source: 'crm'|'user' }
* HouseholdMember { scenarioId, name, relation, dob, dependent, dependenceEnd }
* IncomeItem { scenarioId, type: 'salary'|'side'|'family'|'pension'|'rental', amount, frequency: 'monthly'|'annual', start, end }
* ExpenseItem { scenarioId, type: 'core'|'education'|'health'|'lifestyle', amountMonthly }
* Goal { scenarioId, kind: 'child\_edu'|'child\_marriage'|'home'|'other', todaysCost, targetYear, inflationCategory }
* Asset { scenarioId, kind: 'equity'|'debt'|'real\_estate'|'gold'|'cash', value, expectedReturnPre, expectedReturnPost }
* Liability { scenarioId, principalLeft, rate, emi, endDate }
* MiniRetirement { scenarioId, start, months, incomeDuring, expenseDeltaPct, fundingOrder }
* Lead { scenarioId?, name, email, phone, utm, createdAt }

## Plan Modes – Form Schemas

### Quick Plan (minimal)

* Personal: fullName, dob, retirementAge, spouseDob? (optional)
* MonthlyExpenseTotal (one number)
* Children (array, optional): { name, dob?, eduTodaysCost?, marriageTodaysCost? }
* AssetsLumpSum? (optional)
* Assumptions (optional): returnPre, returnPost, inflationHeadline
* MiniRetirement? (optional): { start, months, incomeDuring, expenseDeltaPct }
  **Validation:** sensible ranges; if absent → use CRM defaults or 0.

### Detailed Plan

Use the full schema above (household members, itemized incomes/expenses, assets, liabilities, goals, mini‑retirements). Any missing numeric → 0; missing assumption → CRM defaults.

## Calculations (server function used by /api/calc)

* Build monthly timeline → roll up to yearly.
* Phase 1: Now→Retirement

  * Grow expenses by inflation; apply income streams with start/end; include mini‑retirement income and expense delta.
  * SIP/surplus assumed reinvested into corpus (simplified).
* Phase 2: Retirement→LifeExpectancy

  * Apply pensions/rental; drawdown using simple guardrail: target real spend based on desired retirement expense; use **returnPost** and **inflationHeadline**.
* Goals: compute future value using category inflation and subtract from corpus in the target year.
* Output:

  * `netWorthSeries: [{year, value}]`
  * `cashflowSeries: [{year, income, expenses, emi, surplus}]`
  * `markers: [{year, type:'retirement'|'mini'|'edu'|'marriage', label}]`
  * `summary: { requiredCorpusAtRetirement, projectedCorpusAtRetirement, gap }`

## Dashboard UI (/plan/\[id])

* **Header**: Scenario name, mode, last updated.
* **KPI tiles**: Required corpus at retirement, projected corpus, gap (₹).
